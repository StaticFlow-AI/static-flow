# Static Flow Frontend

This crate contains the Yew-based client for the Static Flow experience. It renders the blog shell, theme toggles, article detail pages, tag/category listings, site admin, and shared layout in WebAssembly so the UI can stay extremely fast while consuming static or API-provided content.

Codex/Kiro/LLM operator pages (`/admin/llm-gateway*`, `/admin/kiro-gateway*`) are handoff routes into `deps/llm-access/apps/llm-access-frontend` unless the build sets `STATICFLOW_ENABLE_LEGACY_LLM_ADMIN=1`. Do not treat the Yew files under `src/pages/admin_llm_gateway*.rs` or `admin_kiro_gateway*.rs` as the live key/account console.

## Development Environment

- **Rust** toolchain pinned by the repository `rust-toolchain.toml` (currently `nightly-2026-08-21`)
- **wasm32-unknown-unknown** target: `rustup target add wasm32-unknown-unknown`
- **Trunk** CLI for bundling and serving (`cargo install trunk`)
- **Node.js 24**, npm, curl and tar for the driving world build
- Optional: a local backend on `http://127.0.0.1:39080` for API proxy during development

## Common Commands

```bash
# Start the development server with automatic rebuilds
trunk serve

# Create an optimized production bundle in dist/
# For public deployment, use scripts/build_frontend_selfhosted.sh instead
trunk build --release

# Format only changed files (do not run cargo fmt at workspace root)
rustfmt src/changed_file.rs

# Lint with Clippy (fail on warnings by default)
cargo clippy -- -D warnings
```

## 3D blog world

The homepage link **开车逛 3D 博客** opens `/static/world/index.html`. Trunk runs
`world/build.mjs` to assemble the pinned [Folio 2025](https://github.com/brunosimon/folio-2025/tree/70764a94756cc4de564e493c8ba46c4b5fe03ed1)
client and StaticFlow adaptations. The first build downloads the upstream archive
and locked npm dependencies. Later builds reuse the verified inputs under
`$XDG_CACHE_HOME/staticflow/world` (by default `~/.cache/staticflow/world`).
The blog serves the models, engine, decoders and sounds when visitors enter the world.
To build this document alone, run `node world/build.mjs /tmp/staticflow-world-preview`
from this directory.
To run the Playwright driving regression from this directory, set
`STATICFLOW_WORLD_URL` to the preview's `/static/world/index.html` URL and run
`node --test tests/driving_world.test.mjs`.

Visitors can select fullscreen driving while the opening scene loads. Alt+Enter
toggles fullscreen during play. Press C or tap **第一人称** to switch between
the driver's seat and the overhead view while driving or racing. From the
driver's seat, both hands grip the steering wheel and follow the front wheels
as you turn. The key is
configurable in the driving controls. On a controller, tap the right stick to
switch perspective or hold it to zoom the overhead view.
The live minimap opens by default, shows the car
and the current worldline destination, and remembers its collapsed state.
The radio shows the current track and seek bar. Its keyboard button opens
bindings for driving, playback, track selection and seeking. At the worldline
observatory, tune α to recover an archived D-Mail or β to intercept a radio
transmission. The map marks the next receiver. Both messages unlock the final
transmission at the laboratory. The browser remembers the observer's messages
across visits. The public calibration counter is shared. The meter and the
homepage use the same entries in `world-lines.json`.

The exhibits read the existing public catalog APIs. The Axum route `/api/world`
stores the daily race leaderboard, the latest 30 roadside messages and shared
counters in a SQLite file beside the configured content database. For a content
database named `lancedb`, the file is `lancedb.world.sqlite3`. Both blue/green
backend slots use the same file. Static hosting without that endpoint supports
solo driving.

## Workflow & Notes

1. Run `trunk serve` in watch mode for local development. The proxy defined in `Trunk.toml` forwards API calls to the backend at `127.0.0.1:39080`.
2. Format only files you changed with `rustfmt`. Do not run `cargo fmt --all` at the workspace root — it would reformat `deps/lance` and `deps/lancedb` submodules.
3. Static assets go in `static/` and will be copied directly into the final `dist/` bundle.
4. For production self-hosted builds, always use `scripts/build_frontend_selfhosted.sh` (sets `STATICFLOW_API_BASE=/api`). Bare `trunk build --release` falls back to `localhost:3000/api`.

## Article View Analytics Flow

1. Route enters article detail page (`/posts/:id`).
2. Frontend fetches article content, then calls `POST /api/articles/:id/view`.
3. Response returns `total_views`, `today_views`, and `daily_points` (timezone: `Asia/Shanghai`).
4. Header view badge uses `total_views`; trend button opens overlay chart.
5. Overlay can request `GET /api/articles/:id/view-trend?granularity=day&days=30` or `granularity=hour&day=YYYY-MM-DD`.

## UI Copy & Localization

- All user-facing frontend copy is centralized in `src/i18n/`.
- Current active locale is `i18n::current` (currently aliased to `zh_cn`).
- To add another language later:
  1. Add a new locale file (for example `en_us.rs`) under `src/i18n/`.
  2. Keep key/module structure aligned with `zh_cn.rs`.
  3. Switch `pub use zh_cn as current;` in `src/i18n/mod.rs` to the target locale.
- Dynamic copy templates use `fill_one` / `fill_two` helpers in `src/i18n/mod.rs`.
